# Garage experiment notes (portable_cluster slice 1)

**Date:** 2026-10-18, vmk8 cluster, Garage v2.4.1 (chart 0.10.3 from the
upstream git repo, ArgoCD-managed as the `garage` app).

## What was run

- 3-replica StatefulSet on `local-path` PVCs (meta 1Gi, data 20Gi each),
  Kubernetes-native peer discovery (chart installs the GarageNode CRD — no
  bootstrap peers needed), rpcSecret auto-generated by the chart via helm
  `lookup` (stable across Argo re-syncs, no secret in this public repo).
- Layout: all three nodes assigned to zone `vmk8`, 10G capacity each →
  256 partitions replicated 3x, 9.3 GiB effective cluster capacity.

## Results (all verified)

- **S3 round trip**: key + bucket + object written and read back via aws-cli
  against `http://garage:3900` (`s3 cp` up, `s3api get-object` down).
- **Node-kill test**: `kubectl delete pod garage-1`; object read succeeded
  ~3s later during the outage (READ-DURING-OUTAGE-OK) — the surviving replicas
  served it, the ClusterIP service endpoints excluded the dead pod.
- **Local PV semantics**: garage-1's StatefulSet recreation landed on the same
  node (vmk8snode2) with its data PVC intact — WaitForFirstConsumer pinning
  behaves as the blueprint intends.

## Gotchas hit (for future sessions)

- **`bucket allow --owner` does not grant read/write.** Garage permissions are
  separate: owner manages the bucket, but data access needs an explicit
  `garage bucket allow <bucket> --key <key> --read --write`. First put failed
  with `AccessDenied: Operation is not allowed for this key` until that was
  granted.
- **The dxflrs garage image is from-scratch**: no shell, no `ls`; the binary is
  `/garage` (a file, not a directory). Exec as
  `kubectl exec garage-0 -- /garage <command>`.
- **The `amazon/aws-cli` image entrypoint is `aws`** — `kubectl run ... -- sh -c`
  without `--command` silently appends args to `aws`. Always pass `--command`.
- **`aws s3 cp s3://... -` fails against Garage** with a 400 on its leading
  HEAD; `s3api get-object` works fine.
- **Argo shows the garage app perpetually OutOfSync on the StatefulSet**
  (render diff, cosmetic; automated syncs succeed, workloads healthy). Likely
  the chart's helm-lookup rendering. Revisit if it ever blocks a real sync.
